# 字段筛选功能说明

## 功能概述

字段筛选功能允许管理员根据表单字段的具体内容进行精确查询，支持多种筛选条件和运算符。

---

## 支持的筛选条件

### 通用运算符（适用于所有字段类型）

| 运算符 | 说明 | 示例 |
|-------|------|------|
| **等于** | 字段值完全匹配 | 姓名 等于 "张三" |
| **不等于** | 字段值不匹配 | 状态 不等于 "已完成" |
| **包含** | 字段值包含指定文本 | 地址 包含 "北京" |
| **不包含** | 字段值不包含指定文本 | 备注 不包含 "测试" |
| **开头是** | 字段值以指定文本开头 | 订单号 开头是 "ORD" |
| **结尾是** | 字段值以指定文本结尾 | 邮箱 结尾是 "@gmail.com" |
| **为空** | 字段值为空或未填写 | 备注 为空 |
| **不为空** | 字段值已填写 | 电话 不为空 |

### 数字专用运算符

| 运算符 | 说明 | 示例 |
|-------|------|------|
| **大于** | 数值大于指定值 | 年龄 大于 18 |
| **大于等于** | 数值大于或等于指定值 | 金额 大于等于 1000 |
| **小于** | 数值小于指定值 | 数量 小于 10 |
| **小于等于** | 数值小于或等于指定值 | 评分 小于等于 5 |

## 使用方法

### 1. 添加字段筛选条件

1. 在筛选器中展开"字段筛选"面板
2. 点击"+ 添加字段条件"按钮
3. 选择要筛选的字段
4. 选择运算符
5. 输入筛选值（某些运算符如"为空"无需输入值）
6. 点击"查询"按钮

### 2. 多条件组合筛选

- 可以添加多个字段筛选条件
- 所有条件之间是 **AND（与）** 关系
- 只有同时满足所有条件的记录才会被筛选出来

### 3. 删除筛选条件

- 点击每个条件右侧的"删除"按钮即可移除该条件

### 4. 重置所有筛选

- 点击"重置"按钮会清除所有筛选条件（包括字段筛选）

## 字段类型适配

### 文本类型（text, textarea, email, tel, url）
- 支持所有通用运算符
- 区分大小写
- 可以使用"包含"进行模糊搜索

### 数字类型（number）
- 支持所有通用运算符
- **额外支持**：大于、大于等于、小于、小于等于

### 下拉选择（select, radio）
- 支持所有通用运算符
- 提供选项下拉菜单，无需手动输入

### 复选框（checkbox）
- 支持：等于、不等于、为空、不为空
- 值选项：已勾选、未勾选

### 日期类型（date）
- 支持所有通用运算符
- 可以使用比较运算符进行日期范围筛选

## 技术实现

### 前端
- **组件**: `components/submission/SubmissionFilters.js`
- **状态管理**: `hooks/useSubmissionList.js`
- **数据结构**: 
  ```javascript
  {
    id: timestamp,
    field: "fieldKey",      // 字段key
    operator: "equals",     // 运算符
    value: "searchValue"    // 筛选值
  }
  ```

### 后端
- **API**: `app/api/submissions/route.js`
- **数据库查询**: `lib/db.js - getSubmissions()`
- **JSON 字段查询**: 使用 `JSON_EXTRACT` (MySQL) 或 `json_extract` (SQLite)

### SQL 查询示例

**等于查询**:
```sql
-- MySQL
JSON_EXTRACT(data, '$.fieldName') = 'value'

-- SQLite
json_extract(data, '$.fieldName') = 'value'
```

**包含查询**:
```sql
data LIKE '%"fieldName"%value%'
```

**数字比较**:
```sql
-- MySQL
CAST(JSON_EXTRACT(data, '$.amount') AS DECIMAL) > 1000

-- SQLite
CAST(json_extract(data, '$.amount') AS REAL) > 1000
```

## 性能优化建议

### 1. 字段索引
如果某个字段经常被筛选，可以为该字段创建 JSON 索引：

```sql
-- MySQL 8.0+
CREATE INDEX idx_customer_name ON submissions((CAST(JSON_EXTRACT(data, '$.customerName') AS CHAR(100))));

-- SQLite (需要计算列)
ALTER TABLE submissions ADD COLUMN customer_name_virtual TEXT 
  GENERATED ALWAYS AS (json_extract(data, '$.customerName')) VIRTUAL;
CREATE INDEX idx_customer_name ON submissions(customer_name_virtual);
```

### 2. 查询优化
- 优先使用"等于"而不是"包含"
- 避免过多的"不包含"条件
- 数字比较比文本搜索更快

### 3. 分页查询
- 大数据量时使用分页，避免一次性加载
- 合理设置每页条数（建议20-100条）

## 限制与注意事项

1. **字段类型限制**
   - 不支持文件和图片字段的内容筛选
   - 复杂嵌套 JSON 结构可能不支持

2. **性能考虑**
   - JSON 字段查询比普通列查询慢
   - 大量字段筛选条件会影响查询性能
   - 建议筛选条件不超过 5 个

3. **大小写敏感**
   - 默认区分大小写
   - 如需不区分大小写，使用"包含"运算符

4. **特殊字符**
   - 字段值包含引号、反斜杠等特殊字符时需注意
   - 系统会自动处理 JSON 转义

## 常见问题

### Q: 为什么某些字段不能选择？
**A**: 文件和图片类型的字段不支持内容筛选。

### Q: 如何实现"或"关系的筛选？
**A**: 当前版本只支持"与"关系。如需"或"关系，可以分别查询后手动合并。

### Q: 筛选条件太多导致查询变慢怎么办？
**A**: 
1. 减少筛选条件数量
2. 使用更精确的运算符（如"等于"代替"包含"）
3. 考虑为常用字段创建索引

### Q: 能否保存常用的筛选条件？
**A**: 当前版本不支持保存筛选方案，但可以通过浏览器书签保存包含筛选参数的URL。
